# V8 compatibility

V8 uses V5 execution semantics with eight-byte packed routine and string
addresses and eight-byte file-length units. The initial PC is still a byte
address; abbreviations still use two-byte word addresses. The V6/V7 routine
and string offset fields do not apply. See Standard 1.1
[§1, including its closing remarks](https://inform-fiction.org/zmachine/standards/z1point1/sect01.html).

The first milestone reaches the opening input request in all six retained V8
stories: Afflicted, Anchorhead, Lost Pig, Party Foul, Snack Time and Yomomma.
Independent synthetic tests execute routines and strings above 256 KiB and
restore high-PC checkpoints. V8 shares the V5 text, object and display formats.
This is text-interpreter compatibility, not a claim of complete Standard 1.1
conformance or V6 graphics support.

Linux comparisons use documented public calls to an installed Jericho
executable through its Python API. Reference implementation source is not
consulted. Portable tests read `<rom>_vectors.zip` directly with `zipfile` and
verify member and ROM hashes. Archives contain commands, scalar measurements
and hashes, never story text, memory dumps or ROM bytes. Regenerate them with:

```sh
uv run --group reference python -m tests.scripts.generate_zork1_vectors --only v8
```

The public reference uses a 128-column, 232-row header. Comparisons pass those
dimensions explicitly; Fernz's default remains 80 by 25. Opening transcripts
include both windows. Comparison helpers account for the reference's first
character and prompt clipping without changing Fernz's output stream. Snack
Time's literal `>` is preserved separately from its command prompt. The
reference retains an otherwise empty prompt and upper-window status after a
cancelled restart; the comparison retains those together too.

Fernz exposes each real input boundary. The test adapter advances Anchorhead's
three title-screen key requests, Snack Time's one key request, and Party Foul's
first key request and `no` tutorial answer to match public reference reset.
Party Foul then remains at a second character request. These startup actions
belong to the comparison fixture, not the interpreter.

The second milestone covers twelve walkthrough commands per game, parser
errors, nonexistent nouns, repeated waits, snapshots/copies, and story-level
save/restore and restart. All 240 global words are hashed alongside object
entries and property tables. Afflicted's heavier parser paths need more than
the default 250,000-instruction allowance; comprehensive replay explicitly uses
`step(action, max_steps=2_000_000)`. The default library budget is unchanged.

V8 Quetzal files now round-trip through the V5 store-result machinery. Independent
synthetic cases exchange files with Jericho and Frotz in both directions at
PCs above 256 KiB, with seven-argument discarding calls and stack/local results.
Restore failure atomicity and the distinction between opcode RNG preservation
and deterministic host checkpoints are covered for both V5 and V8.

The final milestone adds complete winning routes for Lost Pig and Snack Time
and their story query profiles. Comprehensive V8 checks run in dedicated Linux
and portable jobs; synthetic coverage and one short opening run in quick PR
checks.

## Two complete winning routes

Both routes come from the public `get_walkthrough()` API and run at explicit
host seed 42. Each input is measured live on Linux and replayed from the same
hash records on macOS, Windows x64 and Windows ARM.

| Retained story | Release / serial | Commands | Final / maximum score | Player | World list length, including zero |
| --- | --- | --- | --- | --- | --- |
| `lostpig.z8` | 2 / 080406 | 146 | 6 / 7 | 87 | 536 |
| `snacktime.z8` | 1 / 080929 | 34 | 50 / 50 | 44 | 85 |

Lost Pig's published route is a winning ending with six points, not a maximum
score route. Victory is recognized from measured ending output, never inferred
from the score. The public reference reports both victory and game over there.
Fernz preserves its established API meaning of `game_over()` as a loss: victory
is true and game over is false. The vectors retain both raw reference flags.
Neither ending executes VM `quit`, so Fernz's `step()` done flag stays false
while the ending menu awaits input; the reference's done flag becomes true.

Each turn checks the complete object list, player, immediate parent location,
inventory, score, moves, maximum score, reward and outcome queries. Independent
specification-based decoding of public RAM covers all 48 object attributes,
links, names and property lists. Direct `get_object()` lookups are also checked,
including all objects at startup and rotating objects during play. These reads
must leave the checkpoint unchanged.

Text, all 240 global words, object/property memory, RNG and pending input are
checked throughout both routes. Four checkpoints per route fork and replay a
turn, including the ending. Reset followed by restoring the final checkpoint
recovers the winning state and its flags.

Independent public RAM mutations establish the counter contracts: Lost Pig
uses globals 1 and 2; Snack Time uses globals 2 and 3 (zero-based indices).
Both expose the score's unsigned low byte and an unsigned 16-bit move count.
Vectors check 0, 1, 255, 256, 32767, 32768 and 65535 for each counter. These
host query conventions do not alter instruction execution or stored values.

Profiles match the exact addressable image hash, not the filename. The other
four V8 games have opening, action and persistence coverage but do not yet
have story-specific player/score/outcome profiles or complete route coverage.
The measured outcome coverage here is the two winning endings; no additional
loss path is claimed. Unprofiled stories still support generic object
inspection and deterministic checkpoints.
