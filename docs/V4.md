# V4 compatibility and Trinity

Fernz executes V4 stories using the Z-machine Standard 1.1. This milestone
covers the retained **Trinity release 12, serial 860926**, through its opening,
short command sequences and complete winning walkthrough. It is measured
compatibility, not a claim of complete Standard conformance for every V4 story.

Implementation follows the specification. Jericho and Frotz are used only
through documented public APIs or executable interfaces for black-box testing.
Their implementation source is never inspected.

## Version boundaries

V4 combines the later object layout and longer dictionary keys with earlier
routine and input conventions. The relevant clauses are Standard
[§1](https://inform-fiction.org/zmachine/standards/z1point1/sect01.html),
[§6](https://inform-fiction.org/zmachine/standards/z1point1/sect06.html),
[§8.7](https://inform-fiction.org/zmachine/standards/z1point1/sect08.html#eightseven),
[§11](https://inform-fiction.org/zmachine/standards/z1point1/sect11.html),
[§12](https://inform-fiction.org/zmachine/standards/z1point1/sect12.html),
[§13](https://inform-fiction.org/zmachine/standards/z1point1/sect13.html), and
the [opcode definitions](https://inform-fiction.org/zmachine/standards/z1point1/sect15.html).

- Packed routine/string addresses multiply by four. Routines retain initial
  local-variable words and can receive seven arguments.
- Objects use 14-byte entries, 48 attributes, 16-bit links and up to 63 property
  numbers. Dictionary keys contain nine Z-characters in six bytes.
- `sread` retains NUL-terminated text and one-based token offsets, without a
  stored result. `read_char` stores its result and supports checkpoints/copy.
  Timing requests remain unavailable and unadvertised; zero timing operands
  leave ordinary input active.
- The lower-window cursor starts and remains on the bottom screen row. Window
  erasure returns it to the bottom left; the upper cursor returns to the top
  left. V4 splitting does not perform V3's implicit upper-window clear.
- Header setup changes only fields defined for V4. V5 unit dimensions, font
  dimensions and colour fields are preserved. V4 reports Standard revision
  `0.0`; unavailable timing and file-transcript services are not advertised.
- V4 `save`/`restore` use their original 0OP numbers with a store byte. Quetzal
  retains the store-byte address and restores with result 2. Synthetic tests
  include stack/local destinations, seven-argument frames and PCs above 64 KiB,
  plus file exchange with Jericho and Frotz in both directions.

## Opening and walkthrough

`FernzEnv.reset()` pauses at Trinity's title-screen character request. Send
`step("")` to press Enter and reach the first command prompt. Jericho's public
`reset()` consumes that title request internally; the comparison helper joins
the two Fernz observations. The rich CLI accepts the key directly; the simple
frontend uses Enter to submit it.

The reference's public `get_walkthrough()` supplies **610 commands**. At explicit
seed **0**, both interpreters reach **100/100 points in 608 moves**. The final
command acknowledges the concluding text and reaches the ending menu. The
winning route is seed-sensitive: a probe at seed 42 followed the same commands
but finished without victory at 80 points in both interpreters. Alternate-seed
tests compare 50-command prefixes, without promising a win for every seed.

The exact-image story profile records player object **103**, signed word score
global **154**, unsigned word move global **133**, and maximum score **100**.
Indices are zero-based global-table offsets. Public snapshot perturbations
check counter values through 65535. World enumeration returns 593 real objects
plus the established object-zero placeholder. Inspection remains detached and
does not change a checkpoint.

Outcome detection hashes response lines rather than embedding game prose.
Jericho reports both victory and game-over at the winning menu; Fernz reports
victory without classifying it as a loss, consistent with its other profiles.
Fernz's `step().done` remains false there because the VM is still accepting
menu input. Waiting at the initial location for 36 WAIT commands produces a
measured losing ending; WAIT can advance more than one game move.

## Test vectors and detours

`tests/vectors/trinity_vectors.zip` follows the established per-ROM naming and
hash-verified ZIP format. It contains seven members: a manifest, walkthrough,
detours, lifecycle scenarios, a loss sequence, alternate seeds and counter probes.
It stores commands, numeric metadata and hashes, with no ROM bytes, game prose,
RAM dumps, stack dumps or save payloads.

The tests cover:

- The complete winning route, restoring and replaying every action.
- 53 fixed commands at six route checkpoints: 318 detours with LOOK/INVENTORY
  follow-ups until an outcome. These include unknown verbs, valid verbs with
  missing or nonexistent objects, incomplete commands, uppercase input,
  red herrings, movement, inventory changes and time advancement.
- Save/restore at three checkpoints, rejected and accepted restart, a losing
  sequence, environment copies, counter-width probes and seeds 1, 42 and 1000.
- Text from **both windows**, including boxed quotations; every dynamic-memory
  byte after the 64-byte header; input boundaries; RNG state; reward; counters;
  outcomes; complete object records; player, location and inventory inspection.

The reference uses 128 columns and 232 rows; tests configure that geometry
explicitly. Fernz retains its 80×25 defaults. Text comparison normalizes
whitespace, the reference's initial-character clipping and the final command
prompt. Interior text and punctuation are retained. RAM comparison excludes
only the header, whose capability/identity fields legitimately differ between
hosts; independent tests cover Fernz's V4 header configuration. Full Fernz
checkpoint equality additionally checks its display state during replay.

Linux tests generate expectations directly through public Jericho calls.
Portable tests read the same ZIP through `zipfile`, without extraction or
Jericho. Regenerate or verify it in the Linux Python 3.11 reference environment:

```sh
uv run --group reference poe generate-vectors --only trinity
uv run --group reference poe check-vectors --only trinity
uv run --group reference poe test-v4-reference
uv run poe test-v4-vectors
```

`--only v4` is an alias for the same archive. Fast CI checks its integrity and
runs the opening plus five commands on all platforms, with the same short live
comparison on Linux. Full traversal, detours and freshness checks belong to the
manual comprehensive workflow's V4 jobs.

Sound playback and callbacks, timed input, file streams and the other documented
frontend limitations remain outside this milestone. Header flags continue to
describe the available services honestly.
