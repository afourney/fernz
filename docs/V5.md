# V5 execution milestones

The V5 work is split into three reviewable changes: startup and input, a complete
9:05 playthrough with persistence, and parity with the existing Jericho-style
inspection APIs. All implementation follows the specification. Jericho is run
only through documented public APIs for black-box comparisons; its implementation
source and Frotz's implementation source must not be inspected.

## Milestone 1: first prompt and command input

Fernz executes the retained `905.z5` (V5, release 1, serial `120724`) to its
opening and through `answer phone`, `stand up`, `s`, `remove watch`, and
`remove clothes`. Every continuation also replays from an immutable snapshot.
The CLI can run this story with the same command-line interface as V3 games.

Shared execution now understands the later object-table layout, 48 attributes,
word-sized object links, long properties, nine-Z-character dictionary keys,
custom alphabet and Unicode translation tables, zero-initialized locals,
discarding calls, seven arguments, catch/throw, and counted line input. Character
input suspends independently: `step()` supplies the first character of its
argument (an empty string means Enter), without echoing a line terminator.
Nonzero timed-input operands fail explicitly.

Nested output stream 3 is available in V3 and V5. The logical display defaults
to 80 columns and 25 rows, configurable through constructor options. Both windows
enter the public `Observation.text` transcript in execution order;
`Observation.stream` also records cursor, split, clear, style, font and colour
operations. See [the stream contract](OBSERVATIONS.md). There is no terminal
renderer yet, and transcripts are not word-wrapped. The header advertises only the supported text capabilities
and identifies its Standard 1.0 text semantics. Optional colour, sound,
timed input, and undo capabilities remain unadvertised. This is incremental
execution support, not a claim that every V5 story or operation is implemented.

All new V3 and V5 checkpoints use schema 4, an immutable `GameState` subclass
with an `output` field. It preserves geometry, window selection, cursor positions,
styles, colours, fonts, buffering, and nested output tables. Reference vector
fingerprints use a separate VM-only projection because native snapshots do not
expose these display fields. V5 pending input
also records its result variable and whether it is character input. Restore
validates these fields before changing the environment.

V5 does not define universal score, move, or player globals. Without a measured
story profile, `reset()` and `step()` return empty `info`, rewards are
zero, and story-specific status/player queries raise `NotImplementedError`.
The pinned 9:05 build now has such a profile (milestone 3). Raw object access
uses the correct V5 layout. Other execution versions
remain disabled.

## Milestone 2: complete play and file persistence

The 22-command public reference walkthrough reaches the winning ending. Tests
branch at four positions into 22 commands each, including unknown verbs, absent
nouns, clothing, containers, navigation, waiting, and undo. Additional scenarios
cover the fatal car crash, the office route, the blocked freeway, confirmation
prompts, restart after both endings, cancellation, and actual quit. Each detour
also repeats from a Fernz checkpoint and checks the entire resulting snapshot.

V5 `save` and `restore` write/read Quetzal through the existing host callbacks
and CLI. Save returns 1; restoring resumes that saved instruction with 2;
failure returns 0. Seven arguments, discarded call results, stack destinations,
and addresses above 64 KiB survive interchange. Saved files preserve the
recipient's current RNG and I/O state; host checkpoints retain full replay state.
Auxiliary region I/O remains explicitly unsupported. Undo reports unavailable
(-1), matching the public reference behavior measured for 9:05.

The Standard-version header matters to observable text: this story selects its
article-handling text-capture path from that field. Reporting 0.0 selected a
legacy fallback, producing an incorrect article before the ID card. The office
detour and wallet commands exercise the corrected path.

## Validation

Independent synthetic tests cover the version-dependent formats and operations,
including object numbers above 255, 64-byte properties, seven-argument calls,
discarded results, input continuation, and nested output across snapshot restore.
The existing V3 suites remain unchanged in coverage.

Linux compares 9:05's startup, full route, detours, and persistence directly with Jericho's public API. The portable
suite reads `tests/vectors/905_vectors.zip` in memory on every platform. Its
expectations contain hashes of observations and the entire object/property
region for this exact build, not ROM bytes, narrative, or memory dumps. The
region is `0x010a..0x10a5`, before the globals; host header fields, call frames,
and parser scratch are not claimed as reference-state comparisons at this stage.
Fernz's complete snapshots are independently checked for deterministic replay.

For the existing comparison, Fernz lower-window text is extracted from the
public stream. Normal turns remove exactly the initial input newline and final
`\n\n>` prompt. Driving questions and ending prompts have separate, explicitly asserted
suffixes. Confirmation responses additionally exclude the reference's measured
upper-window status redraw (128 spaces, room, and clock). These narrow adapters
retain all narrative whitespace. The reference reports endings through its
outcome flag while the VM is still accepting restart/restore/quit; Fernz's
`done` continues to mean executed `quit`.

Linux also exchanges synthetic and real-game Quetzal files through public
Jericho calls and synthetic files through the standalone Frotz executable. No
files or memory payloads are committed. The ZIP has nine members: a manifest,
startup, walkthrough, four detour groups, lifecycle scenarios, and seed cases.

```sh
uv run poe test-fast
uv run --no-sync poe test-fast-reference
uv run --no-sync poe generate-vectors --only 905
uv run --no-sync poe check-vectors --only 905
```

Generation and freshness checks require the pinned Linux/Python 3.11 Jericho
environment. Fast CI runs the bounded startup tests; the manual comprehensive
workflow additionally verifies the archive against fresh reference measurements.


## Milestone 3: existing environment APIs on V5

The existing public surface now has live and portable 9:05 coverage:
`reset`, `step`, `copy`, `seed`, `get_state`, `set_state`, `close`, `get_score`,
`get_moves`, `get_max_score`, `game_over`, `victory`, `get_object`,
`get_world_objects(clean=False)`, `get_player_object`, `get_player_location`, and
`get_inventory`. The CLI, storage callbacks, and output callback also work for V5.
There is no new runtime dependency.

The exact 9:05 image profile identifies player 28 and a maximum score of 1.
Black-box snapshot perturbations establish `moves = global[17] - 545`: elapsed
minutes since 9:05, including the shower's six-minute action and driving's
four-minute increments. Its reference score is the latest response's victory
flag, not a persistent game score. Consequently a non-winning reply after the
ending changes score from 1 back to 0 and produces reward -1, matching the public
reference. Ordinary loss and victory flags likewise clear on the next response;
Fernz checkpoints and copies preserve the captured flags. None of these story
conventions changes opcode execution.

Raw inspection includes all 48 V5 attributes, word-sized links, and all property
numbers. The empty world slot has 48 zero attributes too. The reference's public
object wrapper exposes only 32 attribute flags; tests compare that common
projection and independently decode all 48 from its public RAM snapshot. Fernz
continues to retain full names, unnamed nodes, and properties beyond the public
reference's fixed-size wrappers. Direct results and nested lists remain detached.

Every recorded gameplay boundary now includes hashes for world, player, location,
inventory, full attributes, plus numeric status, outcomes, and RNG state. Four
positive host seeds exercise opening and eleven commands through an independent
copy. The V3 deferred-seed, entropy, copy-policy and reset tests now also run on
hand-assembled V5 stories. These establish deterministic Fernz checkpoints; the
native tuple adapter remains V3-only. V5 cross-interpreter file interchange uses
Quetzal as described above.

This milestone validates the complete API against the pinned 9:05 game, not
complete gameplay for all 33 retained V5 builds. An exploratory boot/five-input
survey found object-zero handling in `acorncourt.z5` and property-table traversal
in `inhumane.z5`, `spirit.z5`, and `theatre.z5`; the first broader-validation
phase below resolves those failures.
Other builds completed that bounded probe, but their startup key prompts,
walkthroughs, score/player profiles, and endings still need dedicated tests.
Unknown builds keep raw inspection and explicit errors for unavailable metadata.
Timed input, terminal rendering, auxiliary saves, action discovery, cleaned world
inspection, and world hashing remain outside these three milestones.

## Broader V5 validation: phase 1

The merged V5 baseline passed all 22 jobs in comprehensive run
[38124056422](https://github.com/afourney/fernz/actions/runs/38124056422)
on `dbf0bb2` before this expansion began.

Independent, hand-assembled stories reproduce two legacy behaviors through
Jericho's public API and the packaged Frotz executable:

- `insert_obj` with either operand zero leaves the complete object tree
  unchanged. This is an opcode compatibility extension; object zero still
  does not exist for direct inspection or low-level object operations.
- Some older Inform V5 property lists contain adjacent duplicate numbers.
  Keep their physical order: lookup and update affect the first occurrence;
  `get_next_prop` can return the same number. Enumeration retains both entries.
  Ascending lists, property number zero, and out-of-bounds data remain errors.
  The early V3 property layout retains its existing validation.

These changes resolve the observed Acorn Court, Inhumane, Spirit, and Theatre
startup failures. The same duplicate-property issue also occurs when entering
commands in Curses. Live regressions check the pending input address, RNG, and
complete object-entry region through `look`, `inventory`, and `wait` in all five
ROMs. Theatre's and Curses' initial character prompts are consumed explicitly
in Fernz.

This establishes bounded startup coverage for these paths, not complete game
support. Full-corpus startup vectors and additional winning trajectories follow
in separate changes. All reference work uses documented APIs, executable
behavior, and the Z-machine specifications; implementation source is not read.

## Broader V5 validation: phase 2

Every one of the **33 retained V5 images** now has two bounded scenarios:
`look`, `inventory`, `wait`, an unknown verb and an unknown noun; and the first
five commands returned by the public reference walkthrough API. Both start
from a reset with seed 42. These are startup and continuation checks, not a
claim that each complete walkthrough wins.

The Linux tests generate expectations by running Jericho through its public
Python API. Portable tests replay the same cases from
`tests/vectors/<rom>_vectors.zip`, using `zipfile` in memory. The existing 9:05
archive retains all its full-game coverage and gains a `breadth.json` member.
The other archives initially contain that member and a manifest. Regenerate or
check all V5 archives with `poe generate-vectors --only v5` or
`poe check-vectors --only v5`; individual ROM names also work.

Each boundary checks the pending input instruction and its line/character kind,
RNG, the complete object-entry region (including all 48 attributes), and every
bounded object name/property table. These are hashes of public snapshot RAM
parsed independently from the specified layout. The recorder does not derive
expected execution results from Fernz. Replay also checks checkpoint continuation,
copy independence, and reset reproducibility. The ZIPs contain commands,
metadata, and hashes, without narrative, ROM bytes, memory dumps, or save files.

Startup conventions are explicit. Curses, Library, Loose, Sherlock, Theatre,
and Tryst have one character prompt; Hunter, in Darkness has two. Jewel's public
reset silently executes `bypass` then `yes` while returning its earlier opening
observation. The Fernz helper performs those same story commands and compares
state at the resulting boundary. An unexpected prompt fails instead of consuming
an arbitrary number of keys.

Text comparison here checks content with whitespace normalized. Narrow measured
rules handle reference prompt clipping and Sherlock's upper-window clocks.
Curses, Hunter, Library, Sherlock, and Theatre have upper-window title screens;
their opening records compare state, with narrative comparison beginning at
the next input. This suite does not validate terminal geometry. 9:05's existing
full-game suite retains its stricter whitespace comparisons.

Comprehensive CI has a separate Linux V5 reference/freshness job and a V5
portable group on macOS, Windows x64, and Windows ARM. These cases do not enter
the automatic fast suite. Score, player, maximum score and outcome profiles
remain limited to independently validated games.

The unknown-noun path in Acorn Court also exercises `get_prop` on a property
longer than two bytes. Standard §15 leaves that result undefined. Independent
3-, 8-, and 64-byte-property probes agree in both executables: V5 returns the
word formed by the trailing size byte and the first data byte. Fernz implements
that measured read, bounded within the property block. V3 validation and long
property writes keep their existing behavior.

## Broader V5 validation: phase 3

Balances (release 5, serial `961216`) and Sherlock (release 21, serial `871214`)
now have full-trajectory profiles alongside 9:05. Their public walkthroughs run
with the reference's measured default seed **0**: 122 commands for Balances and
339 for Sherlock. Balances wins with **50 of 51** points; Sherlock wins with
**100 of 100**. A winning route need not obtain the advertised maximum score.

The profiles identify the exact addressable image by SHA-256. Public snapshot
perturbations establish unsigned low-byte score reads from global 1 (Balances)
and 27 (Sherlock), with word-sized move counters at globals 2 and 159. The player
objects are 20 and 232. Outcome detection uses hashes of response lines.
Sherlock reports both `game_over()` and `victory()` at its winning ending.
Fernz still distinguishes these flags from VM quit: it pauses at the ending's
character menu until the caller chooses an option.

The archives include the complete routes, checkpoint detours with valid and
invalid commands, a loss in each game, in-game save/restore, rejected and
confirmed restart, and seeded copies. Every route and detour step is replayed
from its Fernz snapshot and checked for complete checkpoint equality. Live Linux
tests also transfer midgame Quetzal files in both directions and continue to
victory. Both participants execute RESTORE before comparison, so restore-time
story effects are aligned. RNG is controlled separately through public
snapshots because Quetzal deliberately does not save it.

Comparison checks include rewards, score/moves, maximum score, loss/victory,
player, location, complete inventory and world records, every object entry and
property-table hash, pending input, and RNG. An independent specification-based
decoder reads public reference RAM, including all 48 attributes and full names.
The public reference inventory stops at an unnamed child; Fernz retains the
complete chain, just as in V3. Reference object arrays expose only 32 attributes
and 16 property numbers; the independent RAM checks cover the remaining data.

Three execution/inspection details were exposed by these routes:

- Standard §8's remarks explicitly recommend growing a V4/V5 upper window when
  a box quote positions its cursor below the split. Fernz now does so when the
  requested position fits the screen. Moves beyond its right edge use column 1
  on the requested row, matching independent executable probes; invalid rows and
  nonpositive coordinates still fail. This also allows Sherlock saves from the
  reference's wider screen to restore on Fernz's 80-column text display.
- Independent executable probes show that Sherlock's identity treats attribute
  48 writes as no-ops. Fernz limits this to the exact profiled image and leaves
  out-of-range reads and other invalid attributes as errors.
- Sherlock's object 308 has an out-of-order encoded property tail. Its raw
  snapshot preserves that bounded data, including entries beyond the native
  wrapper's 16 slots. This inspection exception is limited to that object in
  the exact image; executable property traversal retains order validation.

Display and input boundaries remain explicit. Observations expose both windows
in execution order, with display commands in the public stream. Existing route
comparisons extract lower-window text from that stream. Sherlock's boxed sign
and plaque text is compared separately by reading upper-window writes from the
same public stream, with hashes in the vectors. No private output hook is needed.
Status redraws, interpreter branding, prompt clipping and whitespace retain their
narrow presentation rules. The complete convenience transcript now includes the
upper-window clue text.

Tests send one key when paused at `read_char`. Sending a whole word can leave
characters in the reference host's input queue, which is outside its public
snapshot tuple. Ordinary line input still receives the complete command.
Public reset automatically advances Sherlock's initial title key; an in-game
restart leaves that key pending in both engines and the scenario sends it
explicitly. These conventions are test orchestration, not story-specific input
behavior in Fernz.
