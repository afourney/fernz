# V5 execution milestones

The V5 work is split into three reviewable changes: startup and input, a complete
9:05 playthrough with persistence, and parity with the existing Jericho-style
inspection APIs. All implementation follows the specification. Jericho is run
only through documented public APIs for black-box comparisons; its implementation
source and Frotz's implementation source must not be inspected.

## Milestone 1: first prompt and command input

Fernz executes the retained `905.z5` (V5, release 1, serial `120724`) to its
opening and through `answer phone`, `stand up`, `s`, `remove watch`, and
`remove clothes`. Every continuation also replays from an immutable snapshot.
The CLI can run this story with the same command-line interface as V3 games.

Shared execution now understands the later object-table layout, 48 attributes,
word-sized object links, long properties, nine-Z-character dictionary keys,
custom alphabet and Unicode translation tables, zero-initialized locals,
discarding calls, seven arguments, catch/throw, and counted line input. Character
input suspends independently: `step()` supplies the first character of its
argument (an empty string means Enter), without echoing a line terminator.
Nonzero timed-input operands fail explicitly.

Nested output stream 3 is available in V3 and V5. V5 has an 80-column, 25-row
logical text display. Lower-window prose enters observations; upper-window
status redraws have independent cursor positions and do not enter the transcript.
This is not a terminal renderer: styles and colours are unrendered, and output
is not word-wrapped. The header advertises only the supported text capabilities
and does not claim full Standard conformance.

Ordinary V3 checkpoints remain schema 2, with unchanged vector fingerprints.
V5 checkpoints and V3 checkpoints suspended inside memory output use schema 3,
an immutable `GameState` subclass with an `output` field. It preserves window
selection, cursor positions, fonts, and nested output tables. V5 pending input
also records its result variable and whether it is character input. Restore
validates these fields before changing the environment.

V5 does not define universal score, move, or player globals. Until a measured
story profile is added, `reset()` and `step()` return empty `info`, rewards are
zero, and story-specific status/player queries raise `NotImplementedError`.
Raw object access already uses the correct V5 layout. File save/restore and
the unavailable undo opcodes are follow-up work; unsupported operations are not
silently interpreted with V3 semantics. Other execution versions remain disabled.

## Validation

Independent synthetic tests cover the version-dependent formats and operations,
including object numbers above 255, 64-byte properties, seven-argument calls,
discarded results, input continuation, and nested output across snapshot restore.
The existing V3 suites remain unchanged in coverage.

Linux compares 9:05's startup directly with Jericho's public API. The portable
suite reads `tests/vectors/905_vectors.zip` in memory on every platform. Its
expectations contain hashes of observations and the entire object/property
region for this exact build, not ROM bytes, narrative, or memory dumps. The
region is `0x010a..0x10a5`, before the globals; host header fields, call frames,
and parser scratch are not claimed as reference-state comparisons at this stage.
Fernz's complete snapshots are independently checked for deterministic replay.

For this prefix, presentation normalization removes exactly the first newline
and the final `\n\n>` prompt; those bytes are explicitly asserted. No other
whitespace or narrative is filtered.

```sh
uv run poe test-fast
uv run --no-sync poe test-fast-reference
uv run --no-sync poe generate-vectors --only 905
uv run --no-sync poe check-vectors --only 905
```

Generation and freshness checks require the pinned Linux/Python 3.11 Jericho
environment. Fast CI runs the bounded startup tests; the manual comprehensive
workflow additionally verifies the archive against fresh reference measurements.
