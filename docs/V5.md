# V5 execution milestones

The V5 work is split into three reviewable changes: startup and input, a complete
9:05 playthrough with persistence, and parity with the existing Jericho-style
inspection APIs. All implementation follows the specification. Jericho is run
only through documented public APIs for black-box comparisons; its implementation
source and Frotz's implementation source must not be inspected.

## Milestone 1: first prompt and command input

Fernz executes the retained `905.z5` (V5, release 1, serial `120724`) to its
opening and through `answer phone`, `stand up`, `s`, `remove watch`, and
`remove clothes`. Every continuation also replays from an immutable snapshot.
The CLI can run this story with the same command-line interface as V3 games.

Shared execution now understands the later object-table layout, 48 attributes,
word-sized object links, long properties, nine-Z-character dictionary keys,
custom alphabet and Unicode translation tables, zero-initialized locals,
discarding calls, seven arguments, catch/throw, and counted line input. Character
input suspends independently: `step()` supplies the first character of its
argument (an empty string means Enter), without echoing a line terminator.
Nonzero timed-input operands fail explicitly.

Nested output stream 3 is available in V3 and V5. V5 has an 80-column, 25-row
logical text display. Lower-window prose enters observations; upper-window
status redraws have independent cursor positions and do not enter the transcript.
This is not a terminal renderer: styles and colours are unrendered, and output
is not word-wrapped. The header advertises only the supported text capabilities
and identifies its Standard 1.0 text semantics. Optional colour, sound,
timed input, and undo capabilities remain unadvertised. This is incremental
execution support, not a claim that every V5 story or operation is implemented.

Ordinary V3 checkpoints remain schema 2, with unchanged vector fingerprints.
V5 checkpoints and V3 checkpoints suspended inside memory output use schema 3,
an immutable `GameState` subclass with an `output` field. It preserves window
selection, cursor positions, fonts, and nested output tables. V5 pending input
also records its result variable and whether it is character input. Restore
validates these fields before changing the environment.

V5 does not define universal score, move, or player globals. Without a measured
story profile, `reset()` and `step()` return empty `info`, rewards are
zero, and story-specific status/player queries raise `NotImplementedError`.
The pinned 9:05 build now has such a profile (milestone 3). Raw object access
uses the correct V5 layout. Other execution versions
remain disabled.

## Milestone 2: complete play and file persistence

The 22-command public reference walkthrough reaches the winning ending. Tests
branch at four positions into 22 commands each, including unknown verbs, absent
nouns, clothing, containers, navigation, waiting, and undo. Additional scenarios
cover the fatal car crash, the office route, the blocked freeway, confirmation
prompts, restart after both endings, cancellation, and actual quit. Each detour
also repeats from a Fernz checkpoint and checks the entire resulting snapshot.

V5 `save` and `restore` write/read Quetzal through the existing host callbacks
and CLI. Save returns 1; restoring resumes that saved instruction with 2;
failure returns 0. Seven arguments, discarded call results, stack destinations,
and addresses above 64 KiB survive interchange. Saved files preserve the
recipient's current RNG and I/O state; host checkpoints retain full replay state.
Auxiliary region I/O remains explicitly unsupported. Undo reports unavailable
(-1), matching the public reference behavior measured for 9:05.

The Standard-version header matters to observable text: this story selects its
article-handling text-capture path from that field. Reporting 0.0 selected a
legacy fallback, producing an incorrect article before the ID card. The office
detour and wallet commands exercise the corrected path.

## Validation

Independent synthetic tests cover the version-dependent formats and operations,
including object numbers above 255, 64-byte properties, seven-argument calls,
discarded results, input continuation, and nested output across snapshot restore.
The existing V3 suites remain unchanged in coverage.

Linux compares 9:05's startup, full route, detours, and persistence directly with Jericho's public API. The portable
suite reads `tests/vectors/905_vectors.zip` in memory on every platform. Its
expectations contain hashes of observations and the entire object/property
region for this exact build, not ROM bytes, narrative, or memory dumps. The
region is `0x010a..0x10a5`, before the globals; host header fields, call frames,
and parser scratch are not claimed as reference-state comparisons at this stage.
Fernz's complete snapshots are independently checked for deterministic replay.

Normal turns remove exactly the initial input newline and final `\n\n>`
prompt. Driving questions and ending prompts have separate, explicitly asserted
suffixes. Confirmation responses additionally exclude the reference's measured
upper-window status redraw (128 spaces, room, and clock). These narrow adapters
retain all narrative whitespace. The reference reports endings through its
outcome flag while the VM is still accepting restart/restore/quit; Fernz's
`done` continues to mean executed `quit`.

Linux also exchanges synthetic and real-game Quetzal files through public
Jericho calls and synthetic files through the standalone Frotz executable. No
files or memory payloads are committed. The ZIP has nine members: a manifest,
startup, walkthrough, four detour groups, lifecycle scenarios, and seed cases.

```sh
uv run poe test-fast
uv run --no-sync poe test-fast-reference
uv run --no-sync poe generate-vectors --only 905
uv run --no-sync poe check-vectors --only 905
```

Generation and freshness checks require the pinned Linux/Python 3.11 Jericho
environment. Fast CI runs the bounded startup tests; the manual comprehensive
workflow additionally verifies the archive against fresh reference measurements.


## Milestone 3: existing environment APIs on V5

The existing public surface now has live and portable 9:05 coverage:
`reset`, `step`, `copy`, `seed`, `get_state`, `set_state`, `close`, `get_score`,
`get_moves`, `get_max_score`, `game_over`, `victory`, `get_object`,
`get_world_objects(clean=False)`, `get_player_object`, `get_player_location`, and
`get_inventory`. The CLI, storage callbacks, and output callback also work for V5.
There is no new runtime dependency.

The exact 9:05 image profile identifies player 28 and a maximum score of 1.
Black-box snapshot perturbations establish `moves = global[17] - 545`: elapsed
minutes since 9:05, including the shower's six-minute action and driving's
four-minute increments. Its reference score is the latest response's victory
flag, not a persistent game score. Consequently a non-winning reply after the
ending changes score from 1 back to 0 and produces reward -1, matching the public
reference. Ordinary loss and victory flags likewise clear on the next response;
Fernz checkpoints and copies preserve the captured flags. None of these story
conventions changes opcode execution.

Raw inspection includes all 48 V5 attributes, word-sized links, and all property
numbers. The empty world slot has 48 zero attributes too. The reference's public
object wrapper exposes only 32 attribute flags; tests compare that common
projection and independently decode all 48 from its public RAM snapshot. Fernz
continues to retain full names, unnamed nodes, and properties beyond the public
reference's fixed-size wrappers. Direct results and nested lists remain detached.

Every recorded gameplay boundary now includes hashes for world, player, location,
inventory, full attributes, plus numeric status, outcomes, and RNG state. Four
positive host seeds exercise opening and eleven commands through an independent
copy. The V3 deferred-seed, entropy, copy-policy and reset tests now also run on
hand-assembled V5 stories. These establish deterministic Fernz checkpoints; the
native tuple adapter remains V3-only. V5 cross-interpreter file interchange uses
Quetzal as described above.

This milestone validates the complete API against the pinned 9:05 game, not
complete gameplay for all 33 retained V5 builds. An exploratory boot/five-input
survey found object-zero handling in `acorncourt.z5` and property-table traversal
in `inhumane.z5`, `spirit.z5`, and `theatre.z5` that need separate investigation.
Other builds completed that bounded probe, but their startup key prompts,
walkthroughs, score/player profiles, and endings still need dedicated tests.
Unknown builds keep raw inspection and explicit errors for unavailable metadata.
Timed input, terminal rendering, auxiliary saves, action discovery, cleaned world
inspection, and world hashing remain outside these three milestones.
